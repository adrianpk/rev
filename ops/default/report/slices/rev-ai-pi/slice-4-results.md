## Purpose

Offer generated text for a captured native target, then apply it only through
explicit acceptance and the editor's canonical checked transaction.

## Delivered Behavior

- ai-prompt asks for an instruction after showing selection replacement or
  point insertion. ai-implement always captures a point, including with an
  active selection. The target is captured before instruction input and checked
  again before Pi starts; missing inputs never widen to whole-buffer editing.
- Fresh input-only operations retain the existing Pi resource/tool profile.
  Replacement supplies its captured selection; insertion supplies the literal
  instruction and point metadata. No reusable definition is written by execution.
- A settled version-1 text result becomes a native read-only proposal with its
  original buffer, revision and range. There is no streamed or implicit source
  application. Explanations have no apply action.
- ai-apply-result requires selecting that proposal. It rechecks source identity,
  revision, visiting association, live read-only state and the result's own
  immutable payload span. Another focused buffer cannot become its target.
- Acceptance consumes publication authority once, preserves generated bytes,
  makes one native undo step and leaves source unsaved. Shared view positions,
  grapheme boundaries, return viewport and undo/redo use existing native owners.
- ai-discard-result closes the proposal without a source edit and safely retires
  shared result views. C-g and owning modal Escape also discard a selected result;
  other prompts keep their cancellation. One pending result must be resolved
  before another invocation. Active cancellation still owns bounded child cleanup.

## Implementation Notes

T4.1/T4.2 land together in
`b9dbf29d6b89f49d1735c15e3104470fba9de1c2`: capture, proposal ownership and
acceptance share one state transition and remain compilable as one implementation
unit. The report introduction adds T4.3 integration coverage and reference updates.

The focused AI target owner retains a native span, point and file association,
not a model-selected destination. Instruction input uses the existing native
argument owner and a 16384-byte limit, also subject to native prompt and total
input limits. Completed proposals keep their text only in the native result
buffer; publication reads a checked payload span rather than a second editable
source or transcript. Native location anchors map return positions after stale
source changes, and missing sources are never implicitly reopened.

The window point owner includes the observed source view as an explicit native
history participant while the pane displays its preview. It completes viewport
mapping before Buffer::publish, maps all live peers in that transaction and
returns the mapped source view. No parallel history, coordinate mapper or file
writer is added. The result authority is consumed immediately after publication,
before presentation/cleanup, so a later cleanup error cannot enable replay.
Canonical completion, modal repeat and LSP/file observation boundaries are
notified after the accepted document publication.

## Contracts Added or Changed

PI03/PI06/PI07 and shared AI03/AI05-AI09/AI14-AI17 now cover checked generated
insertion/replacement. Source changes, undo back to equal bytes, actual external
reload, association changes and closed buffers reject old coordinates. Partial,
cancelled, invalid or excessive output cannot supply application authority.
The Slice 3 input-only context and finite RPC/process boundaries are retained.
